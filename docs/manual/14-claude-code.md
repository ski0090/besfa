# Claude Code로 다루기

[Claude Code](https://claude.com/claude-code)에게 말로 씬 작업을 맡길 수 있습니다. Claude Code가 에디터 없이 게임을 띄워, 씬에 물건을 놓고, 땅을 빚고, 흩뿌리고, 애니메이션 상태 기계를 짜고, 씬 사진을 찍습니다.

## 준비

`besfa new`(또는 허브의 **New project**)로 만든 프로젝트에는 이미 `.mcp.json` 파일이 있습니다. 그 프로젝트 폴더에서 Claude Code를 열면 바로 씁니다.

예전에 만든 프로젝트라면, 프로젝트 폴더에 `.mcp.json` 파일을 만들고 아래 내용을 넣으세요.

```json
{ "mcpServers": { "besfa": { "command": "besfa", "args": ["mcp"] } } }
```

`besfa` 명령이 설치되어 있어야 합니다([설치와 시작](01-getting-started.md#설치)).

## Claude Code Game Studios 더하기

[Claude Code Game Studios](https://github.com/ski0090/Claude-Code-Game-Studios)(CCGS)는 Claude Code로 게임을 만들 때 쓰는 에이전트, 스킬, 훅 모음입니다. 기획 문서, 스프린트, 리뷰, 테스트 같은 개발 과정을 슬래시 명령으로 이끌고, Bevy 0.20 레퍼런스와 `bevy-specialist` 에이전트가 들어 있습니다.

- 허브에서 새 프로젝트를 만들 때 **Add Claude Code Game Studios**를 켜거나, 터미널에서 `besfa new <폴더> --ccgs`로 만듭니다.
- **Git**이 있어야 하고, 만들 때 인터넷으로 CCGS를 받습니다. 받지 못하면 프로젝트를 만들지 않고 이유를 보여 줍니다.
- CCGS는 프로젝트의 `.ccg` 폴더에 git 서브모듈로 들어가고, `.claude/` 등에는 그리로 가는 링크가 생깁니다. Windows에서 링크를 만들려면 **개발자 모드**가 켜져 있어야 합니다(설정 > 시스템 > 개발자용).
- 이 프로젝트를 다른 PC에서 받을 때는 `git clone --recurse-submodules`로 받습니다. CCGS를 새 버전으로 올리려면 `git submodule update --remote .ccg`를 실행하고 커밋합니다.
- 만든 뒤 프로젝트 폴더에서 Claude Code를 열고 `/start`, 이어서 `/setup-engine bevy 0.20`을 실행하면 설정이 끝납니다.

## 쓰는 법

프로젝트 폴더에서 Claude Code를 열고 하고 싶은 일을 말하면 됩니다. 예:

- "씬에 있는 엔티티를 보여 줘"
- "`assets/models/oak-tree.glb`를 원점 근처에 다섯 그루 놓아 줘"
- "지형을 만들고 가운데를 언덕으로 올려 줘"
- "zombie 모델에 idle·walk 상태 기계를 붙여 줘"
- "씬 사진을 찍어 줘"
- "Play하고 플레이어가 보는 화면을 UI까지 찍어 줘"

Claude Code는 `besfa mcp`로 게임을 **창 없이** 편집 상태로 띄우고, 에디터가 쓰는 것과 같은 명령을 게임에 보냅니다. 화면을 띄우지 않으므로 작업 중인 다른 창을 가리지 않습니다. 창이 없어도 사진은 찍힙니다. 씬을 원하는 곳에서 본 사진과, 게임 카메라가 보는 그대로(게임의 UI 포함) 찍은 사진 둘 다 됩니다. 게임에 실행 인자가 있으면(예: 특정 레벨로 시작) 그 인자로 띄울 수도 있습니다. 터미널에서는 `besfa screenshot shots/hud.png`가 게임을 창 없이 띄워 Play하고 플레이어가 보는 화면을 그 파일에 남깁니다.

## 빌드와 테스트

Claude Code(또는 터미널)가 게임을 빌드하거나 테스트할 때는 `cargo` 대신 아래 명령을 쓰게 하세요. 에디터의 Run과 같은 설정으로 빌드하므로, 이미 받아 둔 Bevy 빌드를 다시 쓰고 몇 분씩 다시 빌드하지 않습니다.

| 명령 | 하는 일 |
| --- | --- |
| `besfa build` | 게임을 빌드합니다. |
| `besfa test` | 테스트를 빌드하고 실행합니다. |
| `besfa run` | 게임을 창으로 띄웁니다. `--` 뒤의 인자는 게임이 받습니다. |

빌드가 실패하면 종료 코드 30, 테스트가 실패하면 101로 끝나므로, 둘을 코드로 구분할 수 있습니다.

## 주의

- **에디터와 Claude Code가 같은 프로젝트를 동시에 다루지 마세요.** 둘 다 씬 파일을 쓰므로 한쪽의 변경이 다른 쪽에 덮어쓰입니다. 하나를 닫고 다른 쪽을 쓰세요.
- 에디터의 **Agent 창**에서 Claude에게 맡기면, 그 Claude도 프로젝트의 `.mcp.json`으로 `besfa mcp`를 씁니다. 게임을 빌드하고 실행할 수 있으므로 Claude가 고친 코드도 실행됩니다.
  - Agent 창의 **설정** 탭에서 Claude가 그 프로젝트에서 쓸 수 있는 것을 고릅니다. `.mcp.json`에 있는 서버 가운데 체크한 서버의 도구만 부를 수 있고, 처음에는 `besfa`만 체크되어 있습니다. 서버를 더하거나 빼려면 **.mcp.json 열기**로 파일을 고치세요.
  - **Claude가 커밋하고 푸시하고 풀 리퀘스트를 열게 하기**를 켜면 Claude가 그 프로젝트에서 `git`과 `gh`를 묻지 않고 실행합니다. 처음에는 꺼져 있습니다. 프로젝트의 `.claude/settings.json`에 있는 거부 규칙은 여전히 우선하지만, 적힌 그대로 맞는 명령에만 적용됩니다. 예를 들어 `git push --force`를 막는 규칙은 `git push -f`를 막지 못하므로, 강제 푸시는 GitHub의 브랜치 보호로 막으세요. `gh`는 이 프로젝트뿐 아니라 GitHub 로그인으로 접근할 수 있는 모든 저장소를 다룹니다. 풀 리퀘스트를 열게 하려면 터미널에서 `gh auth login`으로 GitHub CLI에 로그인해 두세요.
  - 설정 탭의 선택은 프로젝트가 아니라 이 컴퓨터의 에이전트 설정에 남습니다. 그래서 프로젝트를 복사하거나 clone하면 GitHub는 꺼진 채로 시작합니다.
  - Codex와 Gemini는 `.mcp.json`을 읽지 않고, 설정 탭의 선택도 받지 않습니다.
  - 에디터는 씬이 저장된 뒤에만 작업을 보냅니다. 작업이 끝나면, 그사이 에디터에서 씬을 고치지 않았을 때 바뀐 씬을 다시 읽습니다. 그래서 에디터를 닫지 않아도 됩니다.
  - 대신 에이전트가 일하는 동안에는 에디터에서 씬을 고치거나 저장하지 마세요. 한쪽이 저장한 것을 다른 쪽이 덮어씁니다.
  - 에이전트가 게임 코드를 바꾸면 에디터와 에이전트가 같은 실행 파일을 다시 빌드합니다. 한쪽 게임이 그 파일을 쥐고 있으면 다른 쪽 빌드가 실패할 수 있습니다.
  - 조직은 여러 개 둘 수 있습니다. Organization 탭 맨 위에서 조직을 고르고, 이름을 고치고, **+ 새 조직**으로 더하고, **...** 메뉴의 **조직 삭제**로 지웁니다. 조직마다 프로젝트의 `besfa/organizations/<이름>.besfa`에 저장됩니다.
  - 조직에 작업을 맡기려면 채팅 탭의 모델 목록 맨 아래 **조직**에서 조직 이름을 고르고 보내세요. 실행하는 동안 Organization 탭은 그 조직을 보여 주고, 다른 조직으로 바꿀 수 없습니다. 에이전트마다 링크 순서대로 채팅에 이름을 달고 답합니다. 생각과 도구 호출은 이름 아래 **생각**에 접혀 있다가 클릭하면 펼쳐집니다. Claude는 하는 말과 도구 호출이 보이지만, 추론 과정 자체는 CLI가 보내지 않아 보이지 않습니다. Codex는 실행 기록이 보이고, Gemini는 답만 보입니다.
  - 조직 작업이 중간에 멈추면(중지, 실패, 에디터를 닫음) 그 채팅의 **보내기** 왼쪽에 **이어서**가 생깁니다. 누르면 아직 끝나지 않은 에이전트부터 다시 실행하고, 끝난 에이전트의 답은 그대로 넘깁니다. 멈춘 에이전트는 처음부터 다시 돌지만, 그 에이전트가 이미 고친 파일은 남아 있습니다. 에디터를 다시 열면 그 채팅이 열린 채로 시작합니다. 새 작업을 보내면 멈춘 작업은 버려집니다.
  - Claude Code Game Studios 역할을 추가하면 조직도의 계층에 따라 모델과 수준이 정해집니다. 디렉터는 Opus에 High, 리드는 Opus에 Medium, 전문가는 Sonnet에 CLI 기본 수준입니다. 노드에서 언제든 바꿀 수 있고, 역할 파일의 `model:`보다 노드에서 고른 모델이 앞섭니다.
  - Organization 탭에서 Claude Code Game Studios 역할을 맡은 에이전트는 그 역할 파일(`.claude/agents/<역할>.md`)의 `tools:` 줄에 적힌 도구만 씁니다. besfa 도구를 쓰게 하려면 그 줄에 `mcp__besfa`를 더하세요. `git`과 `gh`는 그 줄에 `Bash`가 있는 역할만 씁니다. 역할 파일은 `.ccg` 서브모듈 안에 있으므로, CCGS를 새 버전으로 올리면 다시 더해야 할 수 있습니다.
- Claude Code가 쓰는 `besfa mcp`는 CLI를 설치할 때 알던 명령만 받고, 모르는 명령은 거절합니다. 게임의 플러그인을 업데이트해 새 명령이 생겼다면 CLI도 다시 설치하세요([업데이트](13-updating.md#에디터와-cli-업데이트)).
