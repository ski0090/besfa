# Editor UI

`apps/editor_ui`는 Besfa의 Flutter 기반 데스크톱 에디터 UI 프로젝트다.

이 프로젝트는 UI 표시, 사용자 입력, 에디터 상태 표현을 담당한다. Bevy 게임 실행, 프로젝트 파일 생성, 씬 데이터 해석 같은 Rust 도메인 로직은 이 프로젝트에 직접 구현하지 않는다.

## 아키텍처

UI 코드는 [FSD.md](./FSD.md)의 Feature-Sliced Design 규칙을 따른다.

나머지 레이어와 slice는 실제 기능을 만들 때 추가한다. 페이지 사이의 이동은 `app`의 `onGenerateRoute`에서 조립한다.

## 현재 상태

- 프로젝트 생성과 열기를 위한 시작 허브 화면
- Windows 최소 창 크기: 900 × 640
- 새 프로젝트 생성 대화상자에서 대상 경로를 입력하면 PATH의 `besfa` CLI를 `new <DIRECTORY> --output json`으로 실행
- CLI의 JSON 성공·실패 결과를 UI에 표시
- 생성에 성공하면 해당 프로젝트로 에디터 화면(`pages/project_editor`)을 연다
- 프로젝트 열기: 폴더를 선택하면 `Cargo.toml`이 있는지 확인한 뒤 에디터 화면을 연다
- 편집 상태와 실행 상태: 에디터는 프로젝트를 열면 프로젝트 폴더에서 `cargo run --features bevy/dynamic_linking`을 `BESFA_EDIT_MODE=1`로 실행한다 (dynamic linking은 에디터 실행에만 쓰고, 일반 `cargo build`는 단독 실행 파일을 만든다). 게임의 `besfa_editor_plugin`은 이 변수를 보면 `Time<Virtual>`을 멈춘 채 시작하므로, Startup이 만든 씬이 뷰포트에 멈춘 채로 보인다(편집 상태). Play는 게임 stdin에 `play` 한 줄을 보내 시간을 다시 흐르게 하고(실행 상태, 로그도 비운다), Stop은 cargo와 게임 프로세스 트리를 종료한 뒤 편집 상태로 다시 실행한다. 다시 실행하므로 씬이 초기 상태로 돌아가고 코드 변경도 반영된다. cargo가 아직 빌드 중일 때 누른 Play는 파이프에 남았다가 게임이 시작되면 읽힌다. 편집 세션이 빌드 실패나 크래시로 끝났으면 Play가 게임을 실행 상태로 바로 시작한다. 출력은 하단 로그 패널에 표시한다. 시간에 의존하지 않거나 `Time<Real>`을 읽는 시스템은 편집 상태에서도 돈다. 에디터 프로세스는 시작할 때 자신을 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` Job Object에 넣으므로(`windows/runner/main.cpp`), 에디터가 어떻게 종료되든(창 닫기, 크래시, 강제 종료) 빌드 중인 cargo·rustc와 창 없는 게임도 함께 종료된다
- 씬 파일: 게임은 시작할 때 `assets/scenes/main.scn.ron`을 읽어 씬을 만든다 ([DATA_FORMAT.md](./DATA_FORMAT.md)의 '씬 파일'). File > Save scene(Ctrl+S)은 게임 stdin에 `save`를 보내고, 게임이 씬 엔티티들을 같은 파일에 쓴 뒤 `Saved scenes/main.scn.ron` 또는 `Could not save scenes/main.scn.ron: <원인>`을 로그에 남기고 결과를 보고한다. Play 중에는 실행 중 상태가 저장되지 않도록 메뉴가 비활성이다. Stop은 게임을 다시 실행하므로 씬은 파일에 저장된 상태로 돌아간다. 편집 상태에서 씬을 고치면 제목의 프로젝트 이름 뒤에 `*`가 붙고, 저장에 성공하면 지워진다. 저장하지 않은 변경이 있을 때 Play를 누르면 먼저 저장하고(Godot의 기본 동작과 같다) 실행하므로, Stop 뒤에도 Play 전에 고친 내용이 남는다. Back to Project Hub와 창 닫기(제목 표시줄의 닫기 버튼, Alt+F4)는 저장하지 않은 변경이 있으면 Save, Discard, Cancel 중에서 묻는다. Save는 게임이 저장했다고 알린 뒤에 떠나고, 저장에 실패하면 머문다(원인은 로그에 남는다). 편집 세션이 없거나 실행 상태이면 Save는 없다. 창 닫기를 가로채는 것은 편집 화면이 열려 있는 동안뿐이다
- 계층 구조와 인스펙터: 에디터 화면의 왼쪽 Hierarchy 패널은 게임이 보고한 씬 엔티티, 즉 `Name`이나 `Transform`이 있는 엔티티와 그 자식을 `ChildOf` 관계대로 트리로 보여준다 (옵저버와 이벤트용 내부 엔티티 수백 개와, 기즈모 렌더러처럼 게임이 실행되기 전에 Bevy 플러그인이 만든 엔티티는 게임이 보고하지 않는다. 이름이 없으면 Bevy가 출력하는 `4v0` 형식, 게임 코드가 실행 중에 만든 저장되지 않는 엔티티는 흐린 기울임 글자). 항목을 누르면 게임 stdin에 `select`를 보내고, 선택된 항목을 다시 누르면 선택을 지운다. 머리의 + 메뉴는 Empty, Cube, Sphere, Plane, Light, Camera 엔티티를 원점에 만들어 선택하고, 복제(Ctrl+D)와 삭제(Delete, 자식 포함) 버튼이 있다. 입력 칸에 포커스가 있을 때는 Delete와 Ctrl+D가 글자 편집에 쓰인다. 오른쪽 Inspector 패널은 선택한 엔티티의 컴포넌트와 게임의 모든 시스템을 크레이트별로 묶어 보여주고, 게임 자신의 크레이트와 저장되는 컴포넌트가 있는 크레이트를 펼쳐 둔다. Reflect로 등록된 저장되는 컴포넌트의 값은 입력 칸으로 고친다: 숫자와 글자는 Enter나 포커스를 잃을 때, 체크 상자는 누르는 즉시 컴포넌트 값 전체를 `set`으로 보낸다. 입력 중인 칸은 게임이 보낸 새 값으로 덮어쓰지 않는다. 보낸 값은 게임의 보고를 기다리지 않고 바로 인스펙터에 반영하고, 게임이 그 변경을 받기 전에 쓴 보고는 건너뛴다. 그래서 보고가 오기 전에 다른 칸을 고쳐도 앞선 변경이 유지되고, 실행 취소도 마지막으로 보낸 값을 기억한다. 숫자는 소수 셋째 자리까지 보여 주고, Transform의 회전은 쿼터니언 대신 Bevy `EulerRot::YXZ` 각도(X, Y, Z, 도 단위)로 보여 주고 고친다. 다른 컴포넌트에서 계산되는 컴포넌트(`computed`)와 직렬화되지 않는 값은 읽기 전용으로 흐리게 보여 준다. 컴포넌트 머리의 x 버튼은 `remove`를, Add component는 게임이 보고한 추가 가능 컴포넌트 중 엔티티에 없는 것을 검색해 `insert`로 기본값을 붙인다. 다른 컴포넌트가 요구해서 들어온 것이면 `required by X`를, 변경 불가면 `immutable`을, Reflect가 없으면 `no Reflect`를 표시한다. 시스템은 스케줄 이름과 함께 나열한다. 게임이 보고하는 내용은 로그 패널에 나타나지 않는다. Stop으로 게임을 다시 실행하면 보고된 내용은 비우지만 선택은 유지해서 같은 엔티티를 다시 선택한다. Bevy가 컴포넌트와 시스템 이름을 남기도록 플러그인은 `bevy`의 `debug` feature를 켠다
- 플러그인 버전 확인과 갱신: 에디터 툴바는 프로젝트 `Cargo.lock`이 고정한 `besfa_editor_plugin`의 git 커밋을 미리 빌드 프로젝트(`%LOCALAPPDATA%\Besfa\prebuild\Cargo.lock`)의 커밋과 비교해 아이콘으로 보여준다. 같으면 초록 확인 아이콘, 다르면 경고 아이콘이며, 어느 쪽이 새 것인지는 구분하지 않는다. 아이콘을 누르면 프로젝트 폴더에서 `cargo update -p besfa_editor_plugin`을 실행해 GitHub의 최신 커밋으로 올리고(다른 패키지는 건드리지 않는다), 실행 중인 게임을 종료한 뒤 편집 세션을 다시 시작해 새 플러그인으로 다시 빌드한다. cargo의 출력은 로그 패널에 나온다. 미리 빌드가 끝나면 커밋을 다시 읽으므로, 에디터를 켠 채로 push한 커밋은 아이콘을 눌러야 반영된다. 플러그인이 path 의존성이거나 아직 `Cargo.lock`이 없으면 표시하지 않는다
- Bevy 미리 빌드: 에디터가 시작하면 백그라운드에서 `besfa prebuild`를 실행해 공유 target 디렉터리에 Bevy를 에디터의 게임 실행과 같은 feature로 빌드한다. 그래서 `besfa new`로 만든 게임의 실행은 미리 빌드한 Bevy를 재사용하고 게임 코드만 컴파일한다. 미리 빌드가 진행 중인 동안 편집 세션은 시작하지 않고 Play 버튼도 비활성화된다(어차피 cargo가 빌드 디렉터리 잠금을 기다려야 한다). 미리 빌드가 끝나면 편집 세션을 시작한다. 진행 상황은 허브 하단과 에디터 툴바에 한 줄로 표시한다: 실행 중에는 cargo의 마지막 출력 줄과 진행률(`CARGO_TERM_PROGRESS_WHEN=always`로 파이프에서도 켠 cargo 진행 막대의 `완료/전체` 빌드 단위, 이미 빌드된 단위도 완료로 센다), 끝나면 `Bevy is ready` 또는 실패한 종료 코드
- 뷰포트: 게임을 실행할 때 `windows/runner/viewport_texture.cpp`가 D3D11 공유 텍스처를 만들고, 이름을 `BESFA_VIEWPORT` 환경 변수로 게임에 넘긴다. 게임의 `besfa_editor_plugin`이 이 텍스처를 D3D12로 열어(크기와 포맷은 열린 리소스의 `GetDesc()`로 확인한다) 렌더링하고, 에디터는 매 프레임 Flutter용 텍스처로 복사해 `Texture` 위젯에 표시한다. 텍스처는 가운데 패널의 물리 픽셀 크기를 따른다: 패널 크기가 250ms 동안 그대로이면 그 크기로 새 텍스처를 만들어 보여 주고, 게임에 `viewport` 명령으로 이름을 보내 새 텍스처로 옮기게 한다. 옛 텍스처는 실행 중인 게임이 아직 쓰고 있을 수 있으므로 다음 게임을 실행할 때 정리한다. 패널을 알기 전 첫 텍스처는 1280×720이다. 텍스처를 만들 수 없으면 게임은 자체 창으로 실행된다. 게임이 `BESFA_VIEWPORT`를 받았는데 텍스처를 열지 못하면, 오류를 로그에 남기고 종료 코드 1로 끝난다(템플릿의 `main`은 `AppExit`을 반환한다)
- 씬 뷰: 편집 상태의 뷰포트는 게임 카메라 위에 그리는 편집용 카메라(Hierarchy와 씬 파일에는 나오지 않는다)의 화면이다. 처음에는 게임 카메라와 같은 자리에서 같은 곳을 본다. 뷰포트의 포인터는 텍스처 픽셀 좌표로 게임에 `pointer` 명령으로 간다: 오른쪽 끌기는 바라보는 점을 중심으로 돌기, 가운데 끌기는 이동, 휠은 다가가기와 멀어지기, F는 선택한 엔티티로 다가가기다. 왼쪽 클릭은 메시에 광선을 쏘아 맞은 엔티티를 선택하고(빈 곳은 선택 해제) 게임이 `selected`로 알린다. 바닥 그리드와 선택한 엔티티의 경계 상자, 그리고 툴바나 W·E·R로 고르는 이동(월드 축 화살표)·회전(월드 축 고리)·크기(엔티티 축) 핸들을 기즈모로 그리며, 핸들은 늘 위에 같은 화면 크기로 보인다. 핸들을 끌면 그 축으로만 Transform이 바뀌고, 놓으면 게임이 `edited`를 보내 저장하지 않은 변경 표시가 켜진다. 뷰포트 왼쪽 아래에 조작 방법을 보여 준다. Play는 편집용 카메라를 없애고 씬 뷰를 끄므로 게임 카메라의 화면이 보인다. 실행 상태의 게임에는 아직 키보드와 마우스 입력이 가지 않는다
- 되돌리기: Edit 메뉴의 Undo(Ctrl+Z)와 Redo(Ctrl+Y, Ctrl+Shift+Z)는 편집 세션에서 고친 것을 되돌리고 다시 한다: 값 고치기, 씬 뷰에서 핸들 끌기, 컴포넌트 추가와 제거, 엔티티 추가·복제·배치·삭제. 기록은 게임에 보낼 명령으로 남는다. 값을 고치면 이전 값으로 되돌리는 `set`, 핸들 끌기는 게임이 보낸 `edited`의 앞뒤 값, 컴포넌트 추가는 `remove`, 제거는 이전 값으로 다시 붙이는 `set`, 게임이 `spawned`로 알린 엔티티는 `delete`와 `restore`, 삭제는 `restore`와 `delete`다. 삭제한 엔티티는 실행 중인 게임에 숨겨 두므로 엔티티 번호가 그대로이고, 그 뒤의 기록도 그대로 쓸 수 있다. 새로 고치면 다시 하기 목록은 비워지고, 그 때문에 되살릴 수 없게 된 숨긴 엔티티(되돌린 추가·복제·배치)는 `despawn`으로 게임에서 없앤다. 되돌릴 수 있는 삭제는 게임을 다시 시작할 때까지 숨겨 둔다. 게임을 다시 시작하면(Stop, 플러그인 갱신, 다시 빌드) 기록이 모두 비워진다. 입력 칸에 포커스가 있으면 Ctrl+Z는 글자 되돌리기다. 실행 상태에서는 되돌리지 않는다
- 에셋과 프리팹: 아래 패널은 Log와 Assets 탭으로 나뉜다. Assets 탭은 프로젝트의 `assets` 폴더를 폴더 먼저, 이름순 트리로 보여 주고(숨김 파일 제외), 폴더가 바뀌면 저절로 다시 읽는다. glTF 모델(`.glb`, `.gltf`)과 씬·프리팹 파일(`.scn.ron`)은 + 버튼을 누르거나 뷰포트로 끌어 놓으면 `instantiate`로 원점에 파일 이름의 엔티티를 만들고 그 아래에 내용을 펼친다(glTF는 첫 번째 씬). 펼쳐진 내용은 따로 저장되지 않는 흐린 글자로 보이고, 뷰포트에서 클릭하면 그 내용을 담은 저장되는 엔티티를 선택한다. Inspector에서 `DynamicWorldRoot`의 경로를 고치면 다른 프리팹으로 바뀐다. Hierarchy 머리의 Save as prefab은 이름(글자, 숫자, 공백, -, _)을 물은 뒤 `save_prefab`으로 `assets/prefabs/<이름>.scn.ron`을 쓴다
- 코드를 고치면 다시 빌드: 편집 상태에서 프로젝트 `src` 폴더의 `.rs` 파일이 바뀌고 500ms 동안 더 바뀌지 않으면, 로그에 `Source changed; rebuilding.`을 남기고 게임을 종료한 뒤 편집 세션을 다시 시작해 다시 빌드한다. 저장하지 않은 변경이 있으면 먼저 저장하고 게임이 `saved`를 보내거나 5초가 지나기를 기다린다. 실행 상태, 게임을 시작하는 중, Bevy 미리 빌드 중에는 다시 빌드하지 않는다(Stop이 어차피 다시 빌드한다). 마지막 빌드가 실패해 게임이 없을 때도 코드를 고치면 다시 빌드한다
- 최근 프로젝트 목록: 연 프로젝트를 `%APPDATA%\Besfa\recent_projects.json`에 최신순으로 최대 10개 저장한다. 목록에서 연 프로젝트에 `Cargo.toml`이 없으면 목록에서 제거한다. 항목의 폴더 아이콘은 탐색기에서 프로젝트 폴더를 열고, 삭제 아이콘은 확인 후 프로젝트 폴더를 휴지통으로 옮기고 목록에서 제거한다 (`Cargo.toml`이 없는 폴더는 지우지 않고 목록에서만 제거)
