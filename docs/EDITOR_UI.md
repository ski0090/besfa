# Editor UI

`crates/besfa_editor`는 Besfa의 egui 기반 데스크톱 에디터다. `cargo run -p besfa_editor`로 실행한다.

이 crate는 UI 표시, 사용자 입력, 에디터 상태 표현을 담당한다. Bevy 게임 실행, 프로젝트 파일 생성, 씬 데이터 해석은 게임의 `besfa_editor_plugin`과 `besfa` CLI가 맡는다. 그래서 에디터는 Bevy에 의존하지 않는다.

## 아키텍처

eframe이 창을 열고 wgpu로 그린다. 뷰포트 텍스처를 게임과 나누려고 wgpu 백엔드는 DX12로 고정한다. 모듈은 다음과 같다.

| 모듈 | 책임 |
| --- | --- |
| `main` | 앱 조립, 테마와 글꼴, Job Object, 허브와 편집 화면 사이의 전환 |
| `hub` | 프로젝트 허브 |
| `editor` | 편집 화면: 게임 프로세스, 메뉴와 툴바, 단축키, 대화상자 |
| `panels` | Hierarchy, Assets, Log 패널 |
| `inspector` | Inspector와 컴포넌트 값 편집 |
| `preview` | 모델 미리보기 탭의 클립·부품·조명 조작 |
| `sky` | 하늘 탭 |
| `viewport` | 공유 텍스처와 뷰포트의 포인터·키 입력 |
| `scene` | 게임이 보고한 씬과 실행 취소 기록 |
| `process` | 자식 프로세스와 Bevy 미리 빌드 |
| `project` | 최근 프로젝트, 만들기·열기·삭제, 플러그인 커밋 |

egui는 매 프레임 UI를 다시 그리므로 상태는 각 모듈의 구조체에 두고, 자식 프로세스의 출력은 채널로 받아 프레임마다 읽는다. 출력이 오면 UI를 깨운다.

## 현재 상태

- 프로젝트 생성과 열기를 위한 시작 허브 화면
- Windows 최소 창 크기: 900 × 640
- 새 프로젝트 생성 대화상자에서 대상 경로를 입력하면 PATH의 `besfa` CLI를 `new <DIRECTORY> --output json`으로 실행
- CLI의 JSON 성공·실패 결과를 UI에 표시
- 생성에 성공하면 해당 프로젝트로 에디터 화면을 연다
- 프로젝트 열기: 폴더를 선택하면 `Cargo.toml`이 있는지 확인한 뒤 에디터 화면을 연다
- 편집 상태와 실행 상태: 에디터는 프로젝트를 열면 프로젝트 폴더에서 `cargo run --features bevy/dynamic_linking`을 `BESFA_EDIT_MODE=1`로 실행한다 (dynamic linking은 에디터 실행에만 쓰고, 일반 `cargo build`는 단독 실행 파일을 만든다). 게임의 `besfa_editor_plugin`은 이 변수를 보면 `Time<Virtual>`을 멈춘 채 시작하므로, Startup이 만든 씬이 뷰포트에 멈춘 채로 보인다(편집 상태). Play는 게임 stdin에 `play` 한 줄을 보내 시간을 다시 흐르게 하고(실행 상태, 로그도 비운다), Stop은 cargo와 게임 프로세스 트리를 종료한 뒤 편집 상태로 다시 실행한다. 다시 실행하므로 씬이 초기 상태로 돌아가고 코드 변경도 반영된다. cargo가 아직 빌드 중일 때 누른 Play는 파이프에 남았다가 게임이 시작되면 읽힌다. 편집 세션이 빌드 실패나 크래시로 끝났으면 Play가 게임을 실행 상태로 바로 시작한다. 출력은 하단 로그 패널에 표시한다. 시간에 의존하지 않거나 `Time<Real>`을 읽는 시스템은 편집 상태에서도 돈다. 에디터 프로세스는 시작할 때 자신을 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` Job Object에 넣으므로(`src/main.rs`), 에디터가 어떻게 종료되든(창 닫기, 크래시, 강제 종료) 빌드 중인 cargo·rustc와 창 없는 게임도 함께 종료된다
- 씬 파일: 게임은 시작할 때 `assets/scenes/main.scn.ron`을 읽어 씬을 만든다 ([DATA_FORMAT.md](./DATA_FORMAT.md)의 '씬 파일'). File > Save scene(Ctrl+S)은 게임 stdin에 `save`를 보내고, 게임이 씬 엔티티들을 같은 파일에 쓴 뒤 `Saved scenes/main.scn.ron` 또는 `Could not save scenes/main.scn.ron: <원인>`을 로그에 남기고 결과를 보고한다. Play 중에는 실행 중 상태가 저장되지 않도록 메뉴가 비활성이다. Stop은 게임을 다시 실행하므로 씬은 파일에 저장된 상태로 돌아간다. 편집 상태에서 씬을 고치면 창 제목의 프로젝트 이름 뒤에 `*`가 붙고, 저장에 성공하면 지워진다. 저장하지 않은 변경이 있을 때 Play를 누르면 먼저 저장하고(Godot의 기본 동작과 같다) 실행하므로, Stop 뒤에도 Play 전에 고친 내용이 남는다. Back to Project Hub와 창 닫기(제목 표시줄의 닫기 버튼, Alt+F4)는 저장하지 않은 변경이 있으면 Save, Discard, Cancel 중에서 묻는다. Save는 게임이 저장했다고 알린 뒤에 떠나고, 저장에 실패하면 머문다(원인은 로그에 남는다). 편집 세션이 없거나 실행 상태이면 Save는 없다. 창 닫기를 가로채는 것은 편집 화면이 열려 있는 동안뿐이다
- 계층 구조와 인스펙터: 에디터 화면의 왼쪽 Hierarchy 패널은 게임이 보고한 씬 엔티티, 즉 `Name`이나 `Transform`이 있는 엔티티와 그 자식을 `ChildOf` 관계대로 트리로 보여준다 (옵저버와 이벤트용 내부 엔티티 수백 개와, 기즈모 렌더러처럼 게임이 실행되기 전에 Bevy 플러그인이 만든 엔티티는 게임이 보고하지 않는다. 이름이 없으면 Bevy가 출력하는 `4v0` 형식, 게임 코드가 실행 중에 만든 저장되지 않는 엔티티는 흐린 기울임 글자). 항목을 누르면 게임 stdin에 `select`를 보내고, 선택된 항목을 다시 누르면 선택을 지운다. 자식이 있는 항목 앞의 삼각형은 그 아래를 접고 펼친다(Unity처럼 처음과 에디터를 다시 열 때는 접혀 있다). 보이는 줄만 그리므로 엔티티가 수천 개여도 목록이 느려지지 않는다. 접힌 항목 아래의 엔티티가 선택되면(뷰포트 클릭 포함) 그 위의 접힌 항목을 펼쳐 보인다. 머리의 + 메뉴는 Empty, Cube, Sphere, Plane, Light, Camera 엔티티를 원점에 만들어 선택하고, 복제(Ctrl+D)와 삭제(Delete, 자식 포함) 버튼이 있다. 입력 칸에 포커스가 있을 때는 Delete와 Ctrl+D가 글자 편집에 쓰인다. 오른쪽 Inspector 패널은 기본으로 고칠 수 있는 것만 보여 준다: 머리의 이름 칸(`Name`이 있으면 바로 고친다), 씬 파일에 저장되는 Reflect 컴포넌트를 Transform 먼저 한 줄로, 게임 자신의 컴포넌트(Reflect가 없어도), 그리고 게임 자신의 시스템. Bevy가 계산하는 컴포넌트, Reflect 없는 엔진 컴포넌트, Bevy의 시스템, 카메라의 `computed`처럼 실행 중에 다시 계산되는 칸은 숨긴다(숨긴 칸도 값을 고칠 때는 그대로 다시 보낸다). 머리의 Show details 버튼은 자세한 보기로 바꿔, 모든 컴포넌트와 게임의 모든 시스템을 크레이트별로 묶어 보여 주고 게임 자신의 크레이트와 저장되는 컴포넌트가 있는 크레이트를 펼쳐 둔다. Reflect로 등록된 저장되는 컴포넌트의 값은 입력 칸으로 고친다: 숫자와 글자는 Enter나 포커스를 잃을 때, 체크 상자는 누르는 즉시 컴포넌트 값 전체를 `set`으로 보낸다. 입력 중인 칸은 게임이 보낸 새 값으로 덮어쓰지 않는다. 보낸 값은 게임의 보고를 기다리지 않고 바로 인스펙터에 반영하고, 게임이 그 변경을 받기 전에 쓴 보고는 건너뛴다. 그래서 보고가 오기 전에 다른 칸을 고쳐도 앞선 변경이 유지되고, 실행 취소도 마지막으로 보낸 값을 기억한다. 숫자는 소수 셋째 자리까지 보여 주고, Transform의 회전은 쿼터니언 대신 Bevy `EulerRot::YXZ` 각도(X, Y, Z, 도 단위)로 보여 주고 고친다. 다른 컴포넌트에서 계산되는 컴포넌트(`computed`)와 직렬화되지 않는 값은 읽기 전용으로 흐리게 보여 준다. 컴포넌트 머리의 x 버튼은 `remove`를, Add component는 게임이 보고한 추가 가능 컴포넌트 중 엔티티에 없는 것을 검색해 `insert`로 기본값을 붙인다. Reflect가 없으면 `no Reflect`를 표시하고, 자세한 보기에서는 다른 컴포넌트가 요구해서 들어온 것이면 `required by X`를, 계산되는 것이면 `computed`를, 변경 불가면 `immutable`도 표시한다. 시스템은 스케줄 이름과 함께 나열한다. 게임이 보고하는 내용은 로그 패널에 나타나지 않는다. Stop으로 게임을 다시 실행하면 보고된 내용은 비우지만 선택은 유지해서 같은 엔티티를 다시 선택한다. Bevy가 컴포넌트와 시스템 이름을 남기도록 플러그인은 `bevy`의 `debug` feature를 켠다
- 플러그인 버전 확인과 갱신: 에디터 툴바는 프로젝트 `Cargo.lock`이 고정한 `besfa_editor_plugin`의 git 커밋을 미리 빌드 프로젝트(`%LOCALAPPDATA%\Besfa\prebuild\Cargo.lock`)의 커밋과 비교해 아이콘으로 보여준다. 같으면 초록 확인 아이콘, 다르면 경고 아이콘이며, 어느 쪽이 새 것인지는 구분하지 않는다. 아이콘을 누르면 프로젝트 폴더에서 `cargo update -p besfa_editor_plugin`을 실행해 GitHub의 최신 커밋으로 올리고(다른 패키지는 건드리지 않는다), 실행 중인 게임을 종료한 뒤 편집 세션을 다시 시작해 새 플러그인으로 다시 빌드한다. cargo의 출력은 로그 패널에 나온다. 미리 빌드가 끝나면 커밋을 다시 읽으므로, 에디터를 켠 채로 push한 커밋은 아이콘을 눌러야 반영된다. 게임이 첫 보고 `hello`로 알린 프로토콜 버전이 에디터와 다르거나, `hello`가 없는 오래된 플러그인이면 경고 아이콘과 툴팁, 로그로 이유를 알린다. 커밋도 프로토콜 버전도 모르면(플러그인이 path 의존성이거나 아직 `Cargo.lock`이 없고 게임이 아직 보고하지 않았으면) 표시하지 않는다
- Bevy 미리 빌드: 에디터가 시작하면 백그라운드에서 `besfa prebuild`를 실행해 공유 target 디렉터리에 Bevy를 에디터의 게임 실행과 같은 feature로 빌드한다. 그래서 `besfa new`로 만든 게임의 실행은 미리 빌드한 Bevy를 재사용하고 게임 코드만 컴파일한다. 미리 빌드가 진행 중인 동안 편집 세션은 시작하지 않고 Play 버튼도 비활성화된다(어차피 cargo가 빌드 디렉터리 잠금을 기다려야 한다). 미리 빌드가 끝나면 편집 세션을 시작한다. 진행 상황은 허브 하단과 에디터 툴바에 한 줄로 표시한다: 실행 중에는 cargo의 마지막 출력 줄과 진행률(`CARGO_TERM_PROGRESS_WHEN=always`로 파이프에서도 켠 cargo 진행 막대의 `완료/전체` 빌드 단위, 이미 빌드된 단위도 완료로 센다), 끝나면 `Bevy is ready` 또는 실패한 종료 코드
- 뷰포트: 게임을 실행할 때 에디터가 자신의 D3D12 장치에 공유 텍스처(`B8G8R8A8_UNORM_SRGB`, `src/viewport.rs`)를 만들고, 이름 붙은 NT 핸들의 이름을 `BESFA_VIEWPORT` 환경 변수로 게임에 넘긴다. 게임의 `besfa_editor_plugin`이 이 텍스처를 D3D12로 열어(크기와 포맷은 열린 리소스의 `GetDesc()`로 확인한다) 렌더링하고, 에디터는 매 프레임 sRGB 해석 없이 같은 바이트를 egui가 그리는 텍스처로 복사해 표시한다. 텍스처는 가운데 패널의 물리 픽셀 크기를 따른다: 패널 크기가 250ms 동안 그대로이면 그 크기로 새 텍스처를 만들어 보여 주고, 게임에 `viewport` 명령으로 이름을 보내 새 텍스처로 옮기게 한다. 옛 텍스처는 게임이 아직 쓰고 있을 수 있으므로, 게임이 마지막 `viewport` 명령에 `done`으로 답하면 정리하고, 답하지 않는 오래된 플러그인이면 다음 게임을 실행할 때 정리한다. 패널을 알기 전 첫 텍스처는 1280×720이다. 텍스처를 만들 수 없으면 게임은 자체 창으로 실행된다. 게임이 `BESFA_VIEWPORT`를 받았는데 텍스처를 열지 못하면, 오류를 로그에 남기고 종료 코드 1로 끝난다(템플릿의 `main`은 `AppExit`을 반환한다)
- 씬 뷰: 편집 상태의 뷰포트는 편집용 카메라(Hierarchy와 씬 파일에는 나오지 않는다)의 화면이다. 뷰포트나 창에 그리는 게임 카메라는 편집 상태 동안 꺼 두었다가(`is_active`) Play에서 원래대로 켠다(`Parked` 컴포넌트에 원래 값을 둔다). 같은 대상에 두 번째로 그리는 카메라는 Bevy의 MSAA writeback 때문에 첫 카메라의 화면 위에 그리므로, 그대로 두면 시점을 돌릴 때 두 화면이 겹쳐 보인다. 또 Bevy 0.20은 같은 메시를 보는 다른 활성 카메라가 있으면, 그 카메라가 아무 데도 그리지 않더라도(`RenderTarget::None`) 편집용 카메라에 메시를 그리지 않는다. 씬 파일 저장, Inspector, 에디터가 고친 값은 꺼 두기 전의 값을 쓰므로 저장 내용은 바뀌지 않고, 이미지에 그리는 카메라는 그대로 둔다. 처음에는 게임 카메라와 같은 자리에서 같은 곳을 본다. 뷰포트의 포인터는 텍스처 픽셀 좌표로 게임에 `pointer` 명령으로 간다: 오른쪽 끌기는 바라보는 점을 중심으로 돌기, 가운데 끌기는 이동, 휠은 다가가기와 멀어지기, F는 선택한 엔티티로 다가가기다. 오른쪽 버튼을 누른 채 W·A·S·D는 앞·왼쪽·뒤·오른쪽, Q·E는 아래·위(월드 기준)로 날고 Shift는 세 배 빠르다. 빠르기는 바라보는 점까지의 거리를 따른다(초당 그 거리). 그 누름 동안 한 번 날면 오른쪽 끌기는 눈 위치를 둔 채 둘러보기가 된다. 날기 키는 `fly` 명령으로 가므로 게임의 키 입력에는 나타나지 않고, 오른쪽 버튼을 누르고 있는 동안에는 W·E·R 같은 에디터 단축키가 쉰다 왼쪽 클릭은 메시에 광선을 쏘아 맞은 엔티티를 선택하고(빈 곳은 선택 해제) 게임이 `selected`로 알린다. 바닥 그리드와 선택한 엔티티의 경계 상자, 그리고 툴바나 W·E·R로 고르는 이동(월드 축 화살표)·회전(월드 축 고리)·크기(엔티티 축) 핸들을 기즈모로 그리며, 핸들은 늘 위에 같은 화면 크기로 보인다. 핸들을 끌면 그 축으로만 Transform이 바뀌고, 놓으면 게임이 `edited`를 보내 저장하지 않은 변경 표시가 켜진다. 뷰포트 왼쪽 아래에 조작 방법을 보여 준다. Play는 편집용 카메라를 없애고 씬 뷰를 끄므로 게임 카메라의 화면이 보인다. 실행 상태에서는 뷰포트의 포인터가 게임의 마우스가 되고(`ButtonInput<MouseButton>`, `MouseMotion`·`AccumulatedMouseMotion`, `MouseWheel`·`AccumulatedMouseScroll`, 뷰포트 좌표의 `CursorMoved`), 뷰포트에 키보드 포커스가 있으면 키가 게임으로 간다(`ButtonInput<KeyCode>`는 물리 키라 자판 배열과 상관없고, `ButtonInput<Key>`는 이름 있는 키와 입력한 글자). Play를 누르거나 뷰포트를 클릭하면 뷰포트가 포커스를 받고, 바깥을 클릭하면 포커스를 잃으며 게임이 누르고 있던 키를 모두 놓는다. 실행 상태에서는 Delete, Ctrl+D 같은 에디터 단축키가 꺼진다. 게임에는 창이 없으므로 `Window::cursor_position`은 비어 있고, 키를 누르고 있을 때의 반복 입력은 보내지 않는다. Caps Lock과 Ctrl+C·X·V는 게임에 가지 않는다(egui가 Ctrl+C·X·V를 복사·잘라내기·붙여넣기로 바꾼다)
- 되돌리기: Edit 메뉴의 Undo(Ctrl+Z)와 Redo(Ctrl+Y, Ctrl+Shift+Z)는 편집 세션에서 고친 것을 되돌리고 다시 한다: 값 고치기, 씬 뷰에서 핸들 끌기, 컴포넌트 추가와 제거, 엔티티 추가·복제·배치·삭제. 기록은 게임에 보낼 명령으로 남는다. 게임이 `done`으로 실패를 알린 변경(없는 컴포넌트 제거, 맞지 않는 값 등)은 기록에서 빠진다(프로토콜 버전 1 이상의 플러그인). 값을 고치면 이전 값으로 되돌리는 `set`, 핸들 끌기는 게임이 보낸 `edited`의 앞뒤 값, 컴포넌트 추가는 `remove`, 제거는 이전 값으로 다시 붙이는 `set`, 게임이 `spawned`로 알린 엔티티는 `delete`와 `restore`, 삭제는 `restore`와 `delete`다. 삭제한 엔티티는 실행 중인 게임에 숨겨 두므로 엔티티 번호가 그대로이고, 그 뒤의 기록도 그대로 쓸 수 있다. 새로 고치면 다시 하기 목록은 비워지고, 그 때문에 되살릴 수 없게 된 숨긴 엔티티(되돌린 추가·복제·배치)는 `despawn`으로 게임에서 없앤다. 되돌릴 수 있는 삭제는 게임을 다시 시작할 때까지 숨겨 둔다. 게임을 다시 시작하면(Stop, 플러그인 갱신, 다시 빌드) 기록이 모두 비워진다. 입력 칸에 포커스가 있으면 Ctrl+Z는 글자 되돌리기다. 실행 상태에서는 되돌리지 않는다
- 지형: Hierarchy의 + 메뉴의 Terrain은 원점에 256 m 평평한 지형을 만들고 고른다(프로토콜 6 이상의 플러그인일 때만 메뉴에 나온다). 지형을 고르면 Inspector 맨 위에 Terrain 도구가 나온다: Raise·Lower·Smooth·Flatten·Paint 버튼(누른 것을 다시 누르면 끈다), Brush size(m), Strength(0~1, Raise·Lower는 붓 크기의 절반 m가 가장 센 높이다). Paint를 고르면 Layers에 겉면마다 색 버튼과 Layer 1~4가 나오고, 고른 겉면으로 칠한다. 색을 바꾸거나 ➕ Add layer로 겉면을 더하면 `Terrain` 컴포넌트가 바뀌어 되돌리기에 들어가고, 네 개면 Add layer가 꺼지며 "A terrain has at most 4 layers."를 보인다. 붓을 고르면 에디터가 게임에 `terrain_brush`를 보내, 씬 뷰의 왼쪽 버튼이 선택 대신 고른 지형을 칠한다. 마우스 아래 땅에는 붓의 테두리가 땅을 따라 그려지고(그리드처럼 사진에는 들어가지 않는다), 선택한 지형의 핸들은 숨는다. 오른쪽·가운데 버튼과 휠의 카메라 조작은 그대로다. Shift를 누르고 있는 동안 Raise와 Lower는 서로 바뀐다. 누른 뒤 뗄 때까지가 한 획이고, 한 획은 한 번의 되돌리기로 되돌린다(게임이 획이 바꾼 표본의 전후를 기억하고, 되돌리기 기록에서 잊힌 획은 버린다). Esc, 다른 엔티티 고르기, 실행, 미리보기 탭은 붓을 끄고, 뷰포트 왼쪽 아래 안내는 붓을 쓰는 동안 "Paint to sculpt; hold Shift to invert."가 된다. 바뀐 지형 파일은 Save scene에서 함께 저장한다.
- 땅에 내려놓기: Edit 메뉴의 Drop to surface(End)는 선택한 엔티티를 바로 아래 표면으로 내리고, 땅에 묻혔으면 위로 올린다(방향은 그대로). 묶음을 고르면 안의 물건이 각자 내려앉는다. 한 번의 내려놓기는 한 번의 되돌리기로 되돌리고(게임이 옮긴 것의 Transform 전후를 한 번에 알린다), 아래에 표면이 없으면 움직이지 않고 로그에 "No surface below <이름>."을 남긴다. 프로토콜 7 이상의 플러그인이 필요하다.
- 흩뿌리기: 오른쪽 패널은 Inspector, Scatter, Animation 탭으로 나뉜다. Scatter 탭에는 Assets 탭에서 끌어 넣은 프리팹과 모델의 목록(이름, 나올 비율, ✕로 빼기. 비어 있으면 "Drag prefabs or models here to scatter them.")과 Brush size, Density(붓 아래 100 m²당 개수), Spacing, Scale(최소~최대), Random rotation, Align to surface가 있다. 툴바의 ⁙(Scatter) 버튼을 켜면 Scatter 탭이 열리고 지형 붓은 꺼지며, 씬 뷰의 왼쪽 버튼이 선택 대신 붓 아래 땅에 목록의 물건을 흩어 놓는다. Shift를 누르고 칠하면 흩뿌린 것만 지운다(손으로 놓은 것은 남는다). 붓은 이미 있는 흩뿌린 것을 세어 밀도에 모자란 만큼만 더하므로 같은 곳을 다시 칠해도 쌓이지 않는다. 흩뿌린 것은 씬의 Scatter 묶음 아래로 가고, 누른 뒤 뗄 때까지가 한 번의 되돌리기다(처음 칠할 때 만든 Scatter 묶음은 되돌려도 남는다). 붓을 쓰는 동안 땅에 붓의 원이 보이고(지울 때는 붉게), 뷰포트 왼쪽 아래 안내는 "Paint to place; hold Shift to erase."가 된다. Esc나 버튼으로 끈다. 프로토콜 8 이상의 플러그인이 필요하다.
- 에셋과 프리팹: 아래 패널은 Log와 Assets 탭으로 나뉜다. Assets 탭은 프로젝트의 `assets` 폴더를 폴더 먼저, 이름순 트리로 보여 주고(숨김 파일 제외), 폴더가 바뀌면 저절로 다시 읽는다. 내용이 있는 폴더 앞의 삼각형은 그 폴더를 접고 펼친다(처음과 에디터를 다시 열 때는 펼쳐 있다). glTF 모델(`.glb`, `.gltf`)과 씬·프리팹 파일(`.scn.ron`)은 + 버튼을 누르거나 뷰포트로 끌어 놓으면 `instantiate`로 원점에 파일 이름의 엔티티를 만들고 그 아래에 내용을 펼친다(glTF는 첫 번째 씬). 펼쳐진 내용은 따로 저장되지 않는 흐린 글자로 보이고, 뷰포트에서 클릭하면 그 내용을 담은 저장되는 엔티티를 선택한다. 놓인 glTF 모델의 부품을 Hierarchy에서 골라 Inspector로 컴포넌트를 고치면(Visibility를 Hidden으로 얼굴·머리 같은 부품 숨기기, Transform으로 뚜껑 열기 등) 게임이 그 변경을 놓인 루트의 `PartChanges` 컴포넌트에 부품 이름 경로와 함께 기록하고, 씬을 저장할 때 함께 저장해 모델이 펼쳐질 때마다(씬을 읽을 때, 재가져오기 뒤) 다시 건다. 실행 상태에서도 건다. 그런 부품을 고르면 Inspector가 `Part of <파일>; changes to it are saved on the placed model.`로 알려 준다. 루트의 `PartChanges`를 떼면(컴포넌트의 x 버튼) 부품이 파일 그대로 다시 펼쳐지고, 되돌리기로 다시 붙이면 변경도 다시 걸린다. Inspector에서 `DynamicWorldRoot`의 경로를 고치면 다른 프리팹으로 바뀐다. glTF 모델 줄은 아이콘 자리에 모델의 썸네일을 보이고, 이름 위에 마우스를 올리면 큰 썸네일을 보인다. 썸네일은 편집 상태의 게임이 그려 프로젝트의 `target/besfa/thumbnails/<에셋 경로>.png`에 쓰므로(`target`은 버전 관리에서 빠지는 빌드 폴더다) 다음에 열 때도 바로 보인다. 썸네일이 없거나 모델 파일보다 오래되었으면 에디터가 게임에 `thumbnail`을 보내고, 게임을 다시 시작하면 쓰이지 않은 것을 다시 요청한다. 실행 상태에서는 요청하지 않는다. glTF 모델 파일이 바뀌면(Blender에서 다시 내보내기 등) Assets 탭을 보고 있지 않아도 에디터가 알아채고, 다음 확인(1초 뒤)까지 더 바뀌지 않으면 실행 중인 게임에 `reimport`를 보낸다. 게임은 그 파일을 보여 주는 놓인 모델과 미리보기 모델을 새 파일로 다시 펼친다. Assets 탭의 그 파일 줄과 미리보기 패널의 모델 이름 옆에 진행 중이면 회전 표시, 끝나면 5초 동안 ✔, 읽지 못했으면 이유를 툴팁으로 보이는 ⚠가 나오고, 로그에도 남는다. 게임이 실행 중이 아니면 보내지 않는다(게임이 시작할 때 새 파일을 읽는다). 미리보기는 다시 펼쳐도 카메라, 클립, 숨긴 부품, 고른 부품, 패널의 변경을 이름으로 다시 건다. `.gltf`는 그 파일 자체만 보고 `.bin`과 텍스처 파일의 변경은 보지 않는다. Hierarchy 머리의 Save as prefab은 이름(글자, 숫자, 공백, -, _)을 물은 뒤 `save_prefab`으로 `assets/prefabs/<이름>.scn.ron`을 쓴다. 펼쳐진 내용을 고르면 Inspector가 `Part of <파일>; Save scene skips it.`로 어디서 왔는지 알려 준다. 놓인 씬·프리팹이나 그 안쪽을 고르면 Apply to prefab 버튼이 보이고, 누르면 `apply_prefab`으로 프리팹 안쪽의 지금 모습(고친 값, 지운 엔티티 포함)을 그 파일에 쓴다. 게임은 파일을 다시 읽어 같은 파일의 모든 인스턴스를 새로 만들므로, 그 전에 안쪽에서 고친 것은 되돌릴 수 없다. 안쪽에 놓인 다른 프리팹은 경로로만 쓰고, 파일이 자기 자신을 담게 되면 쓰지 않는다. glTF 모델 안쪽은 파일로 되돌려 쓸 수 없고, 씬에 놓은 `scenes/main.scn.ron`에는 Apply to prefab이 없다(게임도 거절한다. 씬 파일을 그 안쪽으로 덮어쓰고 씬 전체를 다시 만들게 된다)
- 애니메이션 상태 기계: 오른쪽 패널의 Animation 탭(Window 메뉴의 Animation State Machine으로도 연다)은 고른 엔티티의 `AnimationStateMachine`을 보여 준다. 없으면 Add state machine 버튼이 그 컴포넌트를 붙이고, 플러그인이 그 컴포넌트를 모르면 갱신을 권한다. 위에는 지금 트는 상태(Playing)와 게임이 쓴 파라미터 값이 보이고, 실행 상태에서는 바뀌는 대로 따라간다. States는 상태마다 이름, 모델의 클립(게임이 보고한 `AnimationClips`에서 고른다), Once, 배속 칸을 보이고, ▶ 표시가 붙은 첫 상태에서 시작한다. ⏶는 그 상태를 첫 상태로 올리고 ✕는 그 상태와 그 상태로 오가는 전이를 지운다. 이름을 바꾸면 전이도 따라 바뀐다. Add state는 아직 쓰지 않은 클립 이름으로 상태를 더한다. Transitions는 전이마다 출발(Any는 모든 상태)과 도착 상태, 크로스페이드 초(Blend s), 넘어가기 전에 틀 클립의 몫(Exit, 0이면 언제든), 조건 목록(시험, 파라미터 이름, Greater·Less의 비교 값)을 보인다. 칸은 포커스를 잃을 때 반영된다. 바꿀 때마다 컴포넌트 전체를 `set`으로 보내므로 Inspector의 변경처럼 되돌리기와 씬 저장에 들어가고, 실행 상태에서 바꾼 것은 Stop하면 사라진다. 편집 상태에서는 게임 시간이 멈춰 있어 클립이 움직이지 않는다.
- 하늘: 오른쪽 패널의 Sky 탭(Window 메뉴의 Sky로도 연다)은 씬의 하늘, 곧 `besfa_editor_plugin::sky::Sky` 컴포넌트를 가진 엔티티를 고친다([SKY.md](./SKY.md)). 탭을 열면 그 엔티티를 선택해 게임이 값을 보고하게 하고, 다른 엔티티를 고른 뒤에는 Edit Sky 버튼으로 다시 고른다. 씬에 하늘이 없으면 "The scene has no sky; the camera's clear color shows."와 ➕ Add sky 버튼(Hierarchy의 + 메뉴의 Sky와 같다)이 나온다. Gradient·Cubemap 버튼으로 방식을 고르고, Gradient는 Zenith·Horizon·Ground 색 버튼과 Blend 막대(지평선 색이 위로 퍼지는 정도), Cubemap은 이미지 경로 칸(Assets 탭에서 `.png`·`.jpg`·`.ktx2`·`.dds`를 끌어 놓아도 된다)을 보인다. Brightness(1이면 고른 색 그대로)와 Rotation(도)은 두 방식에 함께 쓴다. 바꿀 때마다 컴포넌트 전체를 `set`으로 보내므로 편집 상태의 뷰포트에 바로 보이고, Inspector의 변경처럼 되돌리기와 씬 저장에 들어간다. 실행 상태에서는 게임 코드가 바꾸는 값을 따라 보여 주고, 그때 바꾼 것은 Stop하면 사라진다("Changes made in play are gone after Stop."). 프로토콜 10 이상의 플러그인이 필요하고, 오래된 플러그인이면 갱신을 권한다.
- 모델 미리보기: Assets 탭에서 glTF 모델(`.glb`, `.gltf`)을 더블클릭하면 뷰포트 위에 Scene 탭과 모델 탭이 생기고, 게임이 `preview`로 그 모델만 따로 보여 준다. 프로토콜 3 이상의 플러그인이 필요하고, 오래된 플러그인이면 로그로 갱신을 권한다. 모델과 미리보기 전용 카메라·조명은 따로 쓰는 렌더 레이어(31)에 있어서 씬은 보이지도 모델을 비추지도 않고, 모델은 Hierarchy와 씬 파일에 들어가지 않는다. 모델은 게임 월드에 만들어지므로 게임이 glTF에 거는 머티리얼·셰이더 처리를 그대로 받는다. 다만 게임 컴포넌트가 붙은 엔티티에만 거는 처리와 게임 카메라에 붙인 후처리는 받지 않는다. 처음에는 모델 크기에 맞춰 Bevy의 앞쪽(-Z)을 위에서 비스듬히 보고, 왼쪽이나 오른쪽 끌기는 돌기, 가운데 끌기는 이동, 휠은 다가가기와 멀어지기, F는 다시 맞추기다. 바닥에는 1m 간격 그리드와 원점의 X·Y·Z 축을 그린다. 오른쪽 패널은 Inspector 대신 모델 패널이 된다: 파일 이름과 크기(가로 × 높이 × 깊이 m), 삼각형·정점·메시·관절 수, 펼치면 보이는 머티리얼 목록(색, 이름, 쓰는 메시 수, 있는 텍스처), 포함된 애니메이션 클립 목록, 재생·일시정지, 처음으로, 시간 막대(끌면 멈춘 채 그 시간의 자세가 된다), 0.25×·0.5×·1×·2× 배속, 반복, 정해진 시점 버튼(Front·Back·Left·Right·Top·¾, 앞은 모델의 -Z 쪽이다. 고른 시점은 F와 다시 열 때도 쓴다), 뷰포트에 보이는 그대로를 프로젝트의 `screenshots/<모델>-<번호>.png`에 저장하는 Screenshot 버튼(번호는 이미 있는 파일 다음이고, 저장한 경로와 폴더 열기 버튼이 옆에 나온다), 덧그리기(Skeleton: 관절과 부모 관절을 잇는 선, Markers: Grip·ShotPoint처럼 메시 없는 잎 노드인 표시점의 축, Bounds: 경계 상자. 모두 모델 앞에 그리고 스크린샷에도 들어간다. 표시점이 있으면 모델 공간의 위치 목록을 펼쳐 볼 수 있다), Studio·Daylight·Night 조명(게임이 카메라에 노출을 정해 두면 그 노출에 맞춰 밝기를 키운다), 부품 트리(맨 위의 `⛶ 모델` 줄은 모델이 펼쳐진 루트다. 표시점과 관절에는 `marker`·`joint` 표시가 붙고, 패널에서 고친 부품은 강조색이다. 이름을 누르면 그 부품을 고른다. 눈 아이콘은 그 부품과 아래 메시를 숨기고, S는 그 부품만 보여 주고, 머리의 눈 아이콘은 모두 다시 보인다). 고른 부품은 Selected 아래에 이름, Position·Rotation(도)·Scale 끌기 칸, 그리고 Inspector와 같은 컴포넌트 목록과 Add component를 보여 준다. 끌기 칸으로 문 경첩이나 포탑 같은 노드를 돌리고 옮겨 자세를 잡고, 루트에는 게임 컴포넌트를 붙여 게임이 그 컴포넌트가 붙은 모델에만 거는 처리(예: Duskhold의 `CharacterPreview`가 거는 툰 머티리얼)를 미리보기에서 받는다. 클립 목록의 None (rest pose)는 클립을 멈추고 모델을 읽었을 때의 자세로 돌린다. 클립이 움직이는 노드의 자세는 클립이 덮어쓴다. Poses는 지금 바꾼 부품들의 Transform을 이름 붙여 저장하고(Save pose), ▶로 그 자세로 돌리며(먼저 모든 부품을 읽었을 때의 자세로 돌린다), Rest는 바꾼 Transform을 모두 되돌린다. Revert N changes는 패널이 모델에 한 모든 변경을 되돌린다. 패널이 한 변경은 부품 이름 경로로 기억해 모델을 다시 읽을 때(탭을 다시 열 때, 게임을 다시 실행할 때) 다시 건다. 씬의 되돌리기 기록과 저장하지 않은 변경 표시에는 들어가지 않는다. 탭에서 고른 클립·배속·반복·조명·시점·덧그리기·숨김·단독 보기와 변경·자세는 모델마다 프로젝트의 `besfa/previews/<에셋 경로>.besfa`에 저장해 다음에 열 때 그대로 쓴다([DATA_FORMAT.md](./DATA_FORMAT.md)의 '모델 검토 파일'). 파일을 읽지 못하면 패널에 이유를 보이고 그 파일을 덮어쓰지 않는다. 편집 상태의 게임 시간은 멈춰 있으므로 클립은 실제 시간으로 움직인다. 숨기기는 게임이 정해 둔 표시 상태를 기억했다가 되돌린다. 미리보기 탭에서는 씬 단축키(Delete, Ctrl+D, 되돌리기, W·E·R)와 도구 버튼, 뷰포트로 끌어 놓기가 쉰다. Scene 탭으로 돌아가거나 탭을 닫으면 게임은 모델을 버리고, 모델 탭을 다시 누르면 다시 읽는다(클립·배속·반복·조명 선택은 남고, 부품 숨김과 단독 보기는 모델의 루트부터 이어 붙인 부품 이름으로 기억해 같은 이름의 부품에 다시 건다. 다시 내보내 이름이 사라진 부품의 선택은 버린다). 씬이 비어 있는 glTF도 게임이 씬을 펼치면 바로 보고한다. Play는 Scene 탭으로 돌아가며 게임도 미리보기를 닫고, 실행 상태에서는 모델 탭을 누를 수 없다. 코드가 바뀌어 편집 세션이 다시 시작되면 보던 모델을 다시 연다
- 코드를 고치면 다시 빌드: 편집 상태에서 프로젝트 `src` 폴더의 `.rs` 파일이 바뀌고 500ms 동안 더 바뀌지 않으면, 로그에 `Source changed; rebuilding.`을 남기고 게임을 종료한 뒤 편집 세션을 다시 시작해 다시 빌드한다. 저장하지 않은 변경이 있으면 먼저 저장하고 게임이 `saved`를 보내거나 5초가 지나기를 기다린다. 실행 상태, 게임을 시작하는 중, Bevy 미리 빌드 중에는 다시 빌드하지 않는다(Stop이 어차피 다시 빌드한다). 마지막 빌드가 실패해 게임이 없을 때도 코드를 고치면 다시 빌드한다
